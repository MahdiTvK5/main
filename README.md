# OverWall Bot 🛡

ربات کامل فروش و مدیریت سرویس VPN بر پایه‌ی **تلگرام + پنل 3x-UI + PostgreSQL** — همراه با پنل مدیریت وب (NOC دارک)، پورتال اشتراک کاربر، قیمت‌گذاری سه‌سطحی، تمدید خودکار و پرداخت با استارز.

---

## ✨ امکانات

### 🛒 فروش و سرویس‌ها
- خرید کانفیگ با **نام دلخواه کاربر** (اسم دقیق همون در اپ نمایش داده می‌شه؛ فقط در صورت تکرار، شماره‌ی ترتیبی مثل یوزرنیم می‌گیره)
- سه سطح قیمت برای هر پلن: **عادی / VIP / نماینده** — هر سطح فقط ستون خودش رو می‌بینه؛ قیمت خالی یعنی «ناموجود برای اون سطح»
- **آفر خرید اول**، **قیمت ویژه‌ی تمدید** برای هر سطح، **آفرهای کمپینی** (درصدی/مبلغ ثابت با بازه، سقف مصرف و مخاطب) — ارزان‌ترین قیمت برنده‌ست و تخفیف‌ها روی هم سوار نمی‌شن
- **قیمت سفارش منجمد می‌شه** روی خود سفارش؛ تغییر قیمت‌های بعدی روی خریدهای قبلی اثر نداره
- **🤖 تمدید خودکار**: کاربر پلن رو انتخاب می‌کنه؛ یک روز قبل از انقضا اگه موجودی کافی باشه، سرویس بدون دخالتش تمدید و اطلاع‌رسانی می‌شه
- **⏳ یادآوری سه‌مرحله‌ای انقضا**: هشدار اولیه (قابل تنظیم) → فوری ۱ روز قبل → بعد از انقضا؛ هر مرحله فقط یک‌بار + هشدار اتمام حجم (زیر ۱۰٪)
- **📥 ایمپورت کانفیگ** از پنل به کاربر (تکی/گروهی): تشخیص خودکار پلن از روی حجم، جلوگیری از ایمپورتِ تکراریِ سراسری، اطلاع‌رسانی به کاربر
- **🔀 مهاجرت اینباند**: انتقال همه‌ی کلاینت‌ها بین اینباندها **با حفظ UUID** + بازسازی خودکار لینک‌ها و سفارش‌ها (بدون شکستن ساب)

### 💰 کیف پول و پرداخت
- کیف پول با تراکنش‌نامه، شارژ دو روشه:
  - **⭐️ تلگرام استارز** — پرداخت آنی داخل خود تلگرام (نرخ تومان/استارز در پنل تنظیم می‌شود؛ خالی = خاموش)
  - **💳 کارت به کارت** + ارسال رسید و تایید ادمین
- برگشت وجه خودکار در هر خطای پنل (کسر اتمیک؛ هیچ‌وقت پول نمک نمی‌شه)
- **کد هدیه** (اعتبار مستقیم با انقضا، سقف مصرف و مخاطب: همه / کاربر جدید / مشتری فعلی)
- **🔗 سیستم دعوت** با لینک اختصاصی، پاداش معرف و هدیه‌ی دعوت‌شده بعد از اولین شارژ
- **هدیه‌ی اولین شارژ نماینده** + **تخفیف پله‌ای** بر اساس شارژ ۳۰ روز اخیر

### 🎫 مدیریت
- پنل مدیریت داخل بات: پلن‌ها، پنل‌ها (چند 3x-UI)، آفرها، کدهای هدیه، اکانت تست، ایمپورت، گزارش فروش/مالی، پیام همگانی (**با پیش‌نمایش + تأیید** و حالت فوروارد برای حفظ ایموجی‌های پریمیوم)، بن کاربر، مهاجرت اینباند، اجبار عضویت کانال، بکاپ
- **پنل وب مدیریت** (aiohttp، تم تیره NOC): داشبورد KPI + نمودار درآمد ۳۰ روزه + وضعیت زنده‌ی سرورها (پینگ واقعی) + CPU/RAM/Disk واقعی (psutil) + خروجی **CSV فروش/کاربران** + مدیریت کامل کاربران/پلن‌ها/پنل‌ها با احراز هویت نشست‌محور و قفل تلاش ناموفق
- **🚫 بن کاربر**: مسدودسازی بدون حذف تاریخچه (از بات یا پنل وب)
- **⭐️ اجبار عضویت کانال** قبل از /start و خرید (fail-open در خطای API)
- **🚨 هشدار قطعی پنل**: پینگ هر ۳۰ دقیقه؛ ۲ بار پشت‌سرهم down → پیام فوری به ادمین‌ها + پیام برگشت سرویس
- گزارش وضعیت زنده‌ی همه‌ی سرویس‌های کاربر با **یک درخواست به هر پنل** («وضعیت زنده همه»)

### 🌐 پورتال اشتراک
- صفحه‌ی وب اختصاصی هر سرویس: مصرف زنده از 3x-UI، دونات درصدی، انقضا شمسی، اتصال سریع به ۱۲+ اپ (V2RayNG، Happ، Shadowrocket، FlClash و…) با آواتار برند و بج «پیشنهادی»، QR، خروجی Clash
- امنیت با توکن تصادفی (ضد IDOR)؛ هیچ user_id در URL نیست
- **auto-refresh هر ۳۰ ثانیه** با افکت shimmer
- پشتیبانی VLESS / VMess / Trojan با ws/grpc/tcp/xhttp و tls/reality
- هندل درست حالت خاص 3x-UI: انقضای «از اولین اتصال» (expiryTime منفی) بدون کرش

## 🚀 نصب سریع

### ۱) پیش‌نیازها
```bash
sudo apt update && sudo apt install -y python3-venv python3-pip git postgresql postgresql-client
```

### ۲) دیتابیس
```bash
sudo systemctl enable --now postgresql
sudo -u postgres psql -c "CREATE USER overwall_user WITH PASSWORD 'YOUR_STRONG_PASSWORD';" \
  || sudo -u postgres psql -c "ALTER USER overwall_user WITH PASSWORD 'YOUR_STRONG_PASSWORD';"
sudo -u postgres psql -c "CREATE DATABASE overwall_db OWNER overwall_user;"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE overwall_db TO overwall_user;"
```

### ۳) کد و محیط
```bash
git clone <repo-url> overwallbot && cd overwallbot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env && nano .env
```

### ۴) اجرا
```bash
python main.py                      # اجرای دستی
# یا سرویس systemd (پیشنهادی):
bash install_service.sh
```

جدول‌ها و تنظیمات پیش‌فرض در اولین اجرا **خودکار** ساخته می‌شوند؛ مهاجرت‌های بعدی هم افزایشی و idempotent هستند.

> 💡 نصب برنچ جداگانه با دیتابیس/سرویس مستقل: `bash deploy.sh` → گزینه‌ی `b`

## ⚙️ پیکربندی (`.env`)

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات تلگرام |
| `SUPER_ADMIN_ID` | آیدی عددی مدیر کل (خرید رایگان + دسترسی کامل) |
| `PROXY_URL` | پروکسی تلگرام (اختیاری) |
| `PANEL_URL` / `PANEL_USER` / `PANEL_PASS` | پنل پیش‌فرض 3x-UI (فقط برای اولین راه‌اندازی؛ بعدش از «مدیریت پنل‌ها») |
| `CONFIG_IP` | دامنه/IP داخل لینک کانفیگ |
| `DB_USER` / `DB_PASS` / `DB_NAME` / `DB_HOST` / `DB_PORT` | اتصال PostgreSQL (رمز اجباری) |
| `WEB_ADMIN_PASSWORD` | رمز پنل وب؛ خالی = پنل وب اجرا نشود |
| `WEB_HOST` / `WEB_PORT` | پیش‌فرض `127.0.0.1:8080` (پشت Nginx با TLS بگذارید) |
| `PORTAL_PUBLIC_URL` | آدرس عمومی پورتال اشتراک؛ خالی = لینک پورتال در پیام‌ها نمی‌آید |

> ⚠️ تا وقتی شماره کارت و/یا نرخ استارز تنظیم نشده، دکمه‌ی شارژ فقط روش‌های تنظیم‌شده را نشان می‌دهد.

## ⭐️ راه‌اندازی پرداخت استارز

1. پنل وب → **تنظیمات** → «پرداخت با تلگرام استارز» → نرخ را بگذارید (مثلاً `3000` = هر استارز ۳۰۰۰ تومان)
2. کاربر در ربات: شارژ حساب → مبلغ → دکمه‌ی استارز → فاکتور تلگرام → پرداخت → **شارژ آنی**
3. مبلغ از روی `payload` سروری ثبت می‌شود (دستکاری‌ناپذیر)؛ رکورد تراکنش با `telegram_payment_charge_id` لاگ می‌شود

---

## 💳 جریان شارژ با کارت

1. کاربر مبلغ را وارد می‌کند → انتخاب روش → نمایش شماره کارت
2. عکس رسید را می‌فرستد → رسید به همه‌ی ادمین‌ها با دکمه‌ی تایید/رد می‌رود
3. تایید → شارژ خودکار کیف پول + تراکنش

## 🤖 تمدید خودکار — چطور کار می‌کند؟

- کاربر در جزئیات سرویس: «🤖 تمدید خودکار: خاموش» → انتخاب پلن → روشن
- Job هر ۶ ساعت چک می‌کند؛ **۲۴ ساعت قبل از انقضا**: اگر موجودی ≥ قیمت تمدید → کسر + ریست حجم/زمان روی 3x-UI + پیام تأیید
- موجودی ناکافی → پیام هشدار با دکمه‌ی تمدید دستی (فقط یک‌بار)
- شکست پنلی → برگشت وجه خودکار

## 🔀 مهاجرت اینباند (بدون شکستن ساب)

مدیریت ⚙️ → «🔀 مهاجرت اینباند» → بفرستید: `panel_id inbound_مبدا inbound_مقصد` (مثال: `1 613 617`)

- کلاینت‌ها با **همان UUID/پسورد** به مقصد کپی و از مبدأ حذف می‌شوند
- سفارش‌های دیتابیس و لینک‌ها خودکار به مقصد بازنویسی می‌شوند
- کلاینت‌های ناموفق روی مبدأ می‌مانند (هیچ چیز گم نمی‌شود)

> ⚠️ قانون طلایی ساب: کلید اتصال، **email کلاینت** است. email را دستی عوض نکنید؛ تغییر UUID/حجم/اینباند/پورت آزاد است.

## 🌐 پورتال اشتراک

| مسیر | کاربرد |
|---|---|
| `/sub/<token>` | صفحه‌ی وضعیت زنده + اتصال سریع + QR |
| `/sub/<token>/raw` | اشتراک خام Base64 برای همه‌ی کلاینت‌ها |
| `/sub/<token>/clash` | خروجی Clash Meta |

تنظیم `PORTAL_PUBLIC_URL` لازم است تا ربات لینک را در پیام‌ها بگذارد. مسیرها عمومی‌اند؛ امنیت فقط با توکن.

## 🖥 پنل وب

اگر `WEB_ADMIN_PASSWORD` تنظیم شود روی `WEB_HOST:WEB_PORT` بالا می‌آید:
- **داشبورد**: KPI (درآمد خالص/فروش امروز/کاربران/سفارش‌ها)، نمودار درآمد ۳۰ روزه با درصد رشد، وضعیت زنده‌ی سرورها، سلامت سیستم، منابع واقعی، سفارش‌های اخیر، تایم‌لاین فعالیت
- **مدیریت کامل**: کاربران (بن/موجودی/نقش)، پلن‌ها، پنل‌ها، آفرها، کدهای هدیه، تنظیمات (شامل نرخ استارز و کانال اجبار عضویت)
- **CSV**: دکمه‌های خروجی فروش/کاربران در بالای داشبورد (سازگار با Excel)
- **امنیت**: نشست تصادفی با انقضا، قفل IP بعد از ۵ ورود ناموفق، خروج سمت سرور، پیش‌فرض bind روی 127.0.0.1

نمونه‌ی Nginx + TLS در انتهای همین فایل.

## 🔧 نگهداری
- **لاگ**: `bot.log` با چرخش خودکار (۵ مگ × ۳ نسخه) — لاگ‌های مهم: `PURCHASE`, `RENEW`, `AUTO_RENEW`, `STARS_PAY`, `WEB_LOGIN`, `BROADCAST`
- **بکاپ**: مدیریت ⚙️ → 💾 بکاپ (نیاز به `pg_dump`) + بکاپ خودکار روزانه از تنظیمات
- **سرویس**: `systemctl status overwallbot` · `journalctl -u overwallbot -f`

## ❓ عیب‌یابی سریع

| مشکل | علت رایج |
|---|---|
| `ConnectionRefusedError :5432` | سرویس PostgreSQL روشن نیست |
| دو ربات با یک توکن | خطای Conflict — فقط یک نمونه اجرا کنید |
| دکمه‌ی استارز دیده نمی‌شود | نرخ استارز در تنظیمات خالی است |
| پورتال «یافت نشد» | کلاینت روی پنل حذف شده یا email عوض شده |
| بعد از تغییر دستی پنل ساب خراب است | در ربات «📊 بروزرسانی» را بزنید تا لینک با پنل سینک شود |

## 🔐 Nginx پیشنهادی برای پنل وب/پورتال

```nginx
server {
    listen 443 ssl;
    server_name panel.example.com;
    ssl_certificate     /etc/letsencrypt/live/panel.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/panel.example.com/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
```bash
sudo certbot --nginx -d panel.example.com
```
